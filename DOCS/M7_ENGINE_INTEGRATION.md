Engine B locks stature without independently calibrated scale. It excludes unresolved orientation, out-of-range estimated yaw and unreliable framing, and attenuates estimated registration in contour fitting. It records evidence sources, exclusions, G1 parity, bounded optimization and rebind rejections. The optimizer uses the G4 symmetric contour, occupancy and internal gap terms, with a compact CPU sweep and the installed OpenCV rasterizer. The advance toward a better-scoring rejected candidate preserves the M6 rebind check. G4 Lab performance figures remain scoped to their controlled datasets.

Load an optional calibration JSON through Diagnostics & Settings with Engine B selected. Schema version 1 accepts `views`, keyed by `photo_sha256`. Each entry declares boolean `canonical_pose` and `independent_scale` fields, and a `camera` with G4's `yaw`, `span` and optional `center_y`, `elevation`, `distance`, `perspective`, `roll`, `dx`, `dy`. Use the exact oriented square photograph matching its SHA-256. G4 uses centimetres for calibrated camera parameters. For articulated views, set `canonical_pose` to false. Alternatively supply `capture_yaw_sector` in degrees and optionally `focal_px_on_384` in place of the calibrated camera. G3 reports the landmark parity alternative, silhouette IoU, camera uncertainty and numerical rank. It excludes unreliable estimates and keeps metric scale unknown. This registration governs anatomical fitting. Target pose, texturing and the empirical overlay use the existing M6 image estimate and identify that provenance in diagnostics.

Setup verifies the existing hashed dependency locks, the baseline manifest and 582 upstream G1 target files. The registry contains dependency expressions and sampled parity controls generated by the pinned G1 oracle. The application uses its own sparse evaluator and approved MakeHuman geometry data. A failed B attempt stays a B failure. Use the engine selector to request A.
